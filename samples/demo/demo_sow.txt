1. PURPOSE
--------------------------------------------------------------------------------

This Statement of Work defines the scope, timeline, fees, deliverables,
assumptions, and exclusions for Phase 1 of the CareOps Portal engagement.
Phase 1 delivers a staff-facing web application and REST API integration to
support referral intake and clinician operational visibility. Work outside this
document requires a written Change Request.

--------------------------------------------------------------------------------
2. PROJECT SUMMARY
--------------------------------------------------------------------------------

Vendor will design, build, test, and deploy a production-ready CareOps web
portal for Meridian internal staff, integrated with Client’s existing EHR via
read-oriented REST APIs, with SAML-based staff authentication against Client’s
Okta tenant.

Commercial envelope for Phase 1:
  • Fixed fee: USD $120,000
  • Change requests: billed separately under Section 8
  • Client internal approval note: incremental changes above USD $15,000 require
    CFO co-signature on the Client side (Client governance; informational only)

--------------------------------------------------------------------------------
3. IN-SCOPE SERVICES AND DELIVERABLES
--------------------------------------------------------------------------------

3.1 Web application (staff-facing)
  a. Clinician operations dashboard (filters, referral queues, status views)
  b. Referral intake forms with field validation and error messaging
  c. Role-based access control for staff roles defined in discovery
  d. In-app and email notifications for internal staff events
  e. Simple CSV export of on-screen referral list fields (same columns visible
     in the UI; no custom report builder)

3.2 API integration
  a. REST integration to Client EHR read APIs as specified in the integration
     design workshop
  b. Handling for documented rate limits (including caching where appropriate)
  c. OpenAPI / REST API documentation package
  d. No EHR write-back beyond scopes explicitly listed in the integration
     design appendix (default: read-only for Phase 1)

3.3 Authentication and security
  a. Staff SSO via SAML 2.0 against Client Okta tenant
  b. Security walkthrough support for Client information security reviewers
  c. Deployment runbook including rollback outline for production cutover

3.4 Program delivery cadence
  a. Weekly status reports uploaded to the Client shared project folder
  b. Mid-engagement syncs and go-live readiness checkpoints
  c. Train-the-trainer session and materials for care coordinator leads
     (one virtual session, up to 60 minutes)

3.5 Acceptance deliverables checklist
  a. Production-ready CareOps web application (Phase 1 feature set)
  b. API documentation (including caching / rate-limit notes)
  c. Deployment runbook
  d. Training materials for train-the-trainer
  e. Phase 1 acceptance certificate (signed at go-live acceptance)

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
6. EXCLUSIONS (NOT IN PHASE 1)
--------------------------------------------------------------------------------

The following are expressly out of scope for Phase 1 and require a Change
Request or a separate Phase 2 SOW:

6.1 Native mobile applications (iOS and/or Android)
6.2 Offline mode / offline-first field data capture and sync
6.3 Patient-facing consumer applications or patient portals
6.4 Patient SMS / text message notifications or marketing messages
6.5 Custom analytics warehouses, BI tool embedding, or scheduled report packs
    beyond simple on-screen CSV export
6.6 EHR write-back or order entry unless listed in the signed integration
    appendix
6.7 Migration of historical data beyond the mutually agreed cutover dataset
6.8 24/7 managed SOC services (hypercare support is limited as in Section 7)

--------------------------------------------------------------------------------

10.4 No concurrent major EHR vendor upgrade during UAT without joint risk plan
